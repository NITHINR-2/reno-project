# Decisions

One line per assumption or design choice, with its reason. Newest at the bottom of each phase.

## Phase 0 — Scaffold

- **Spring Boot 4.1.1 instead of 3.x** — Initializr only offers 4.x and 3.5 OSS support has ended; chosen by the project owner on 2026-10-10. CLAUDE.md stack line updated.
- **JUnit 6 (Jupiter 6.0.3) instead of JUnit 5** — it is what Boot 4.1 manages; the Jupiter API used in tests is unchanged.
- **springdoc-openapi 3.1.1** — the 3.x line is the one built for Spring Boot 4 / Framework 7.
- **Maven Wrapper 3.10.0 (script-only distribution)** — generated by Initializr; no wrapper JAR is committed.
- **JVM runs in UTC** (`TimeZone.setDefault` in `main`, `-Duser.timezone=UTC` for Surefire and `spring-boot:run`, `hibernate.jdbc.time_zone=UTC`) — Windows reports the legacy zone id `Asia/Calcutta`, which postgres:16 rejects at connect time; UTC storage is also correct practice, and IST (`Asia/Kolkata`) will be applied explicitly for SLA logic.
- **Single `application.yml` with `dev` and `test` profile documents** — keeps all config in one place, as the Phase 0 prompt asks.
- **Backend reads local secrets via `spring.config.import: optional:file:.env[.properties]`** — no extra dependency; `backend/.env` is git-ignored and `.env.example` documents the keys.
- **No default DB password anywhere in committed config** — compose fails fast if `POSTGRES_PASSWORD` is unset; the backend gets `DB_PASSWORD` from `backend/.env`. Follows "never commit secrets".
- **Test profile uses Testcontainers `@ServiceConnection` (postgres:16)** — tests are independent of the local compose database and match production's major version.
- **Flyway `V1__baseline.sql` is a no-op** — it exercises the Flyway wiring and history table before business tables exist.
- **`GET /api/health` is a custom endpoint (not Actuator)** — the prompt asks for this exact path; it reports `status`, `database` (via `SELECT 1`), `version` and `timestamp`, and returns 503 when the database is down.
- **Health endpoint and OpenAPI docs are `permitAll`; everything else requires authentication and returns 401** — secure-by-default baseline until JWT auth lands.
- **CSRF disabled and session policy STATELESS** — the API will be bearer-token based; the refresh-cookie CSRF guard (`X-Requested-With`) is added with the auth phase, per CLAUDE.md.
- **`GlobalExceptionHandler extends ResponseEntityExceptionHandler`** — gives ProblemDetail for all of Spring MVC's built-in exceptions plus a catch-all 500 that hides internals.
- **Health tests are `*Test`, not `*IT`** — the Boot parent doesn't bind Failsafe, so `*IT` classes would silently not run under `./mvnw verify`.
- **Vite 8 template's oxlint kept as the linter** — it is what `create-vite` 9 generates and `npm run lint` already uses it; no need to add ESLint.
- **TypeScript `strict: true` added explicitly** — the current Vite template no longer sets it, and CLAUDE.md requires strict mode.
- **Tailwind CSS v4 via `@tailwindcss/vite`** — the current official integration; no `tailwind.config.js` or PostCSS config needed. Brand tokens (`accent`, `charcoal`) are defined in `@theme`.
- **React Router 8 in data-router mode (`createBrowserRouter`)** — current stable; library mode keeps the SPA simple and leaves room for loaders later.
- **`@/` path alias → `src/`** — defined in both tsconfig and Vite.
- **Vitest without globals; explicit imports plus a `cleanup` in `src/test/setup.ts`** — avoids leaking global types into app code.
- **Health response validated with Zod on the client** — catches contract drift early; the backend stays the source of truth.
- **The Vite proxy target is configurable through `VITE_API_PROXY_TARGET`** (default `http://localhost:8080`).
